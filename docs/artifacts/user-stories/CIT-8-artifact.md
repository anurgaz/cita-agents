## Что мне нужно от BA Agent

Чтобы спроектировать API для создания услуги, необходимо получить US с ответами на следующие вопросы:

**Бизнес-логика:**

1. Кто создаёт услугу? Только `ADMIN`? Или также `STAFF`? `OWNER`?
2. Обязательна ли привязка к категории (`category_id`) при создании, или услуга может существовать без категории (согласно data-dictionary.md — `category_id` nullable)?
3. Каковы ограничения на `price`: может ли быть `0` (бесплатная услуга)?
4. Каковы ограничения на `duration`? Согласно **C-004**: `duration ∈ [1, 480]` минут — BA должен подтвердить верхнюю границу в user story.
5. После создания услуга сразу `is_active=True` (default по data-dictionary.md)? Или провайдер должен явно активировать?
6. Нужно ли сразу привязывать мастеров к услуге при создании (M2M `master_services`), или это отдельный шаг?
7. Есть ли ограничение на количество услуг в рамках одного бизнеса?

**UX / AC:**

8. Что происходит при попытке создать услугу с уже существующим именем в рамках этого бизнеса — дубли разрешены или HTTP 409?
9. Нужен ли side effect: уведомление в Telegram провайдеру при создании услуги?

**Ограничения, требующие подтверждения в AC:**

- **C-004** (минимальная длительность ≥ 1 мин, максимум 480 мин) — должно быть отражено в AC
- **C-008** (JWT 8 дней для Admin) — endpoint защищён Bearer JWT, AC должен описывать поведение при истёкшем токене
- **C-011** (автоназначение мастера при бронировании) — создание услуги без привязанных мастеров допустимо, но влияет на логику бронирования; BA должен подтвердить, нужно ли предупреждение

**Формулировка запроса к BA:**

> "Мне нужна user story для US-XXX «Создание услуги провайдером» с acceptance criteria. Конкретно необходимо уточнить: роли (ADMIN/STAFF/OWNER), обязательность категории, ограничения price/duration (с учётом C-004), поведение при дублировании имени, нужна ли привязка мастеров в момент создания, и side effects (Telegram-уведомление). Также прошу явно отразить в AC поведение при нарушении C-004 и C-008."
