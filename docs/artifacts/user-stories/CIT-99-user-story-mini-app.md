## Шаг 1. Уточнение scope

Задача: описать функциональность просмотра клиентом списка своих записей (bookings) в Telegram Mini App — все статусы, все мастера, все бизнесы. Клиент аутентифицирован через Telegram (role=CUSTOMER).

---

## Шаг 2. Проверка правил и ограничений

**Затронутые constraints:**
- **C-002** — телефон и Telegram ID клиента не должны появляться в логах в открытом виде
- **C-008** — JWT для клиента: уточнить TTL (в constraints описан только Admin/SuperAdmin — ⚠️ пробел, см. Open Questions)
- **C-010** — цена в истории = `price_snapshot`, не текущая `Service.price`
- **C-001** — контекст: при отображении истории overlap не релевантен, но статус double booking может присутствовать как `confirmed`

**Потенциально затронутые business rules:** расписание нерелевантно; жизненный цикл бронирования (pending → confirmed → completed / cancelled / rejected) — релевантен.

**Decision matrix:** задача в зоне BA (генерация user story + AC). API-дизайн для endpoint истории — передаётся SA агенту.

## Story

**Как** клиент, аутентифицированный в Telegram Mini App,
**я хочу** видеть список всех своих записей с их статусами и деталями,
**чтобы** отслеживать предстоящие записи, просматривать прошлые и понимать текущее состояние каждой записи.

---

## Priority

**Must Have**

*Обоснование:* без истории записей клиент не может управлять своими взаимодействиями с провайдерами. Это базовая функциональность CRM-стороны клиента.

---

## Scope

### In Scope
- Список всех записей клиента во всех бизнесах
- Отображение статуса каждой записи (pending / confirmed / completed / cancelled / rejected)
- Отображение ключевых деталей: название услуги, имя мастера, дата и время, цена (`price_snapshot`)
- Разделение на вкладки / секции: «Предстоящие» и «Прошедшие»
- Пустое состояние (empty state) когда записей нет

### Out of Scope
- Отмена записи клиентом из истории (отдельная user story)
- Перенос записи клиентом (отдельная user story — работает через RescheduleProposal)
- Повторная запись в один клик (could have, отдельная user story)
- Рейтинг и отзывы (не реализовано, техдолг — `glossary.md` п.21)
- Напоминания (не реализовано, техдолг — `glossary.md` п.12)
- Просмотр истории администратором или мастером

## Acceptance Criteria

### AC-1: Клиент видит список своих записей

```
Given: клиент аутентифицирован в Telegram Mini App (role=CUSTOMER)
  And: у клиента есть хотя бы одна запись в любом статусе

When: клиент открывает раздел «Мои записи»

Then: отображается список записей, отсортированный по дате (ближайшие первые для предстоящих, последние первые для прошедших)
  And: каждая запись содержит: название услуги, имя мастера, название бизнеса, дату и время, статус, цену из price_snapshot (C-010)
  And: статус отображается на русском языке с визуальным индикатором (цвет / иконка)
```

### AC-2: Разделение на предстоящие и прошедшие записи

```
Given: клиент находится в разделе «Мои записи»
  And: у клиента есть записи с датой в будущем (статусы: pending, confirmed)
  And: у клиента есть записи с датой в прошлом (статусы: completed, cancelled, rejected)

When: страница загружается

Then: предстоящие записи отображаются в секции «Предстоящие» (или активной вкладке)
  And: прошедшие записи отображаются в секции «История»
  And: записи со статусом cancelled и rejected попадают в секцию «История» независимо от даты
```

### AC-3: Пустое состояние

```
Given: клиент аутентифицирован в Telegram Mini App
  And: у клиента нет ни одной записи

When: клиент открывает раздел «Мои записи»

Then: отображается пустое состояние с сообщением (например: «У вас пока нет записей»)
  And: присутствует CTA-кнопка или подсказка для создания первой записи
  And: список не показывает ошибку, спиннер не зависает
```

### AC-4: Детальная карточка записи

```
Given: клиент находится в списке «Мои записи»
  And: список содержит хотя бы одну запись

When: клиент нажимает на карточку записи

Then: открывается детальный экран записи с полными данными:
  - услуга (название, длительность, цена из price_snapshot)
  - мастер (имя)
  - бизнес (название, адрес)
  - дата и время
  - статус с расшифровкой
  And: для записей со статусом confirmed отображается адрес бизнеса
```

### AC-5: Корректное отображение price_snapshot

```
Given: запись была создана с price_snapshot=5000₸
  And: после создания записи владелец изменил цену услуги на 6000₸

When: клиент просматривает эту запись в истории

Then: отображается цена 5000₸ (зафиксированная на момент записи)
  And: текущая цена услуги (6000₸) НЕ отображается в карточке записи (C-010)
```

### AC-6: Идентификация клиента через Telegram

```
Given: клиент открывает Mini App через Telegram
  And: аутентификация выполнена через initData + HMAC-SHA256

When: система загружает историю записей

Then: возвращаются ТОЛЬКО записи данного клиента (по его Telegram ID / phone)
  And: записи других клиентов недоступны
  And: в логах запроса телефон и Telegram ID клиента не отображаются в открытом виде (C-002)
```

## Business Scenarios

### Happy Path
1. Клиент открывает Telegram Mini App → нажимает «Мои записи»
2. Система идентифицирует клиента по Telegram initData
3. Загружается список записей, разделённый на «Предстоящие» и «История»
4. Клиент нажимает на предстоящую запись (статус: confirmed) → видит адрес бизнеса
5. Клиент нажимает на прошедшую запись (статус: completed) → видит детали и зафиксированную цену

### Альтернативный сценарий: нет записей
1. Клиент только зарегистрировался / ещё не создавал записей
2. Отображается пустое состояние с призывом записаться

### Альтернативный сценарий: запись отменена провайдером
1. Провайдер отменил запись (статус: cancelled)
2. Запись отображается в секции «История» с индикатором «Отменено»
3. Клиент видит, что запись была отменена, но не может её восстановить из этого экрана

### Edge Cases

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| E-1 | Клиент записан к мастеру из разных бизнесов | Все записи отображаются в одном списке; бизнес указан в карточке |
| E-2 | Запись в статусе `pending` — провайдер ещё не подтвердил | Отображается в «Предстоящих» с индикатором «Ожидает подтверждения» |
| E-3 | Запись в статусе `rejected` | Отображается в «Истории» с индикатором «Отклонено» |
| E-4 | У записи есть активный RescheduleProposal (статус PENDING) | Отображается специальный индикатор «Предложен перенос» + детали нового времени (C-006) |
| E-5 | Клиент не привязал Telegram-аккаунт к номеру телефона | Записи не найдены или требуется привязка — уточнить в Open Questions |
| E-6 | Ошибка загрузки (сеть, 500) | Отображается сообщение об ошибке с кнопкой «Повторить» |
| E-7 | Очень длинный список (100+ записей) | Пагинация или бесконечная прокрутка — уточнить в Open Questions |
